## 2. دورة التنفيذ

`Engine.run()` تدور حتى تصل الجلسة إلى حالة نهائية أو حالة انتظار:

0. **توجيه النيّة** (`routeIntent` باستعمال `classifyIntent` في `intent.ts`) — قبل أول دورة: أي نوع هذه الرسالة؟ الجلسة المثبّتة (TASK/GOAL يدوياً) لا تُصنَّف؛ العمل غير المنتهي يبقى عملاً؛ غير ذلك يُصنَّف، والنموذج يملك الكلمة الأخيرة بأداة `escalate`. الدردشة بلا أدوات، السؤال بأدوات قراءة، والعمل بكل الأدوات. **الردّ النصي في الدردشة/السؤال ينهي الدور** (`ready`) — لا تكرار.
1. **حقن التعليمات المتأخرة** — أي `follow-up` كتبه المستخدم أثناء العمل يُحقن في بداية الدورة الآمنة التالية، ويُسجَّل دوره (`appliedAtTurn`) ليكون شفافاً.
2. **فحص الميزانية** — `maxTurns` / `maxDurationMs` / `maxModelCalls`. تحذيرات عند 70% (راجع الشروط) و80% (أوقف العمل غير الأساسي) و90% (نقطة تقرير إجبارية) — كل تحذير يُطلق مرة واحدة فقط.
3. **استدعاء النموذج** — رسالة النظام (`prompt.ts`) + النص + النسخة المختصرة من النص السابق + تعليمات المتابعة.
4. **تنفيذ الأدوات** — كل استدعاء يمرّ through `authorize()` الوحيد (انظر §4). النتيجة تُسجَّل في النص كرسالة `tool`.
5. **كشف توقف التقدم** — دورات بلا نص ولا أدوات ولا أدلة تُحوِّل الجلسة إلى `waiting_user` بدل استهلاك الميزانية بلا طائل.
6. **التكرار** — تُكرَّر حتى الإكمال أو الفشل أو توقف المستخدم.

**ضد تكرار الفشل**: فشلتين متتاليتين لنفس الأداة يفرضان تغيير استراتيجية، لا إعادة محاولة عمياء.

### JSON تالف من النموذج

النماذج تُخرج أحياناً JSON ناقصاً في استدعاء أداة. `repairTruncatedJson()` يرمّزه عند الإمكان؛ إن تعذّر، يُعاد الخطأ للنموذج كنص يفهمه (بدل انهيار الحلقة).

## 3. آلة الحالات

`SessionState` في `types.ts` — كل انتقال له سبب مسجّل (`stateReason`):

| الحالة | المعنى |
| --- | --- |
| `idle` | أُنشئت ولم تبدأ |
| `running` | الحلقة نشطة، تقبل رسائل متابعة عند نقاط آمنة |
| `waiting_user` | الوكيل أوقف نفسه وينتظر قرارك (أو توقف تقدّم) |
| `paused` | أوقفها المستخدم — الحالة محفوظة والرسائل تتراكم |
| `interrupted` | العملية ماتت أثناء الدورة — **لا تُفترض الدورة السابقة ناجحة** |
| `completed` | الشروط تحققت والأدلة سُجّلت |
| `failed` | استُنفدت المحاولات/الميزانية مع سبب |
| `stopped` | إيقاف يدوي |

**الاستعادة من الانقطاع** (مهمة): أي جلسة تُفتح وحالتها `running` تُحوَّل إلى `interrupted` برسالة صريحة للنموذج: "افحص ما في المجلد وأكمل — لا تفترض نجاح السابق". هذا يمنع أسوأ سيناريو: مواصلة بناء فوق أساس مفترض.

### المبدأ الجوهري

الصلاحيات **تُفرض على الأداة نفسها**، لا بتعليم النموذج ألا يكتب. الممر الوحيد لكل تنفيذ هو `authorize()` في `tools/permissions.ts`:

1. `checkToolAllowed` — وضع `plan` يرفض أي أداة غير `readonly`. أداة shell في plan ممنوعة كلياً لأنها ثغرة تتجاوز حظر الكتابة.
2. `guard` خاص بالأداة (يحقن `cwd`، يفحص المسارات …).
3. `checkModePolicy` — **الوضع المخصّص** للجلسة (§7.6.1) لا يستطيع إلا إضافة رفض: قوائم السماح والمنع للأدوات، وتُخفى الأداة الممنوعة عن النموذج أيضاً.
4. سياسة الأوامر في `checkCommandAllowed` (وتُقيَّم قوائم أوامر الوضع المخصّص أخيراً؛ ومع قائمة سماح تُرفض الاستبدالات والتحويلات `` ` `` و`$()` و`<` و`>` لأنها تُخفي أمراً ثانياً):
   - **مدمّرة دائماً**: `rm -rf /`، `mkfs`، `format C:` … → رفض قاطع.
   - **نشر**: `git push`، `gh repo create/edit/delete`، `gh api POST/PATCH/DELETE`، `npm publish`، `docker push` → ممنوعة ما لم تُفعَّل `allowPublish` لهذه الجلسة.

## 5. مسار الإثبات (قلب المشروع)

```
النموذج يستدعي complete ──► يُرفض إن لم يغطِّ كل شرط برقم
      │
      ▼
المحرك (لا النموذج) يجمع الدليل باستقلال:
   • الملفات المتغيرة فعلياً
   • حالة git
   • أمر التحقق المُهيّأ (مثل npm test) ── رمز الخروج الحقيقي
      │
      ▼
فشل التحقق؟ ── نعم ──► الرفض + سبب واضح + الجلسة تكمل أو تفشل
      │ لا
      ▼
القبول + سجل الأدلة (EvidenceRecord) في الجلسة
```

نقطتان تستحقان الانتباه:

- `activeRequirements` تشمل كل شرط نشط: الشروط الأصلية + كل follow-up مُطبَّق. رفض `complete` يحدث حين يتجاهل النموذج شرطاً أُضيف أثناء الطريق.
- **`verifiedRequirements` الإلزامية**: ادعاء بـ "تحقق 0 من 0" ليس نجاحاً — النموذج يجب أن يردّ على كل شرط برقم.

الأدلة تُكتب في `session.evidence` **من المحرك فقط**. النموذج لا يملك كتابة سجل الأدلة.

## 6. أساس حقيقة التكلفة (unknown ≠ 0)

المشكلة: النموذج يدّعي اكتمال شيء لم يكتمل، والنظام يعرض "التكلفة $0.0000" وكأن القياس تم.

الحل في VARA طبقتان:

1. **دفتر استدعاءات** (`ModelCallRecord[]`): كل استدعاء نموذج يُسجَّل مستقلاً — الرموز كما أفاد بها المزوّد (`usageSource: 'provider'`) أو كما قدّرناها (`'estimated'`)، والتكلفة أو `null` مع سبب. مجاميع الجلسة **تُشتق من الدفتر كله**، لا تُزاد في المكان — فلا ازدواج عند الاستئناف أو إعادة التشغيل.
2. **الرفض الذهبي**: الرموز غير المُبلَّغ عنها تبقى `null` ولا تصبح 0. التكلفة تُحسب فقط من تسعير صريح في سجلّ النماذج (`llm/registry.ts`)؛ وإلا `costUsd: null` + `unpricedCalls` يعدّ غير المعروفات.

الواجهة تعرض `unknown` صريحاً (وقد تضيف `+` عند وجود جزء غير مُسعّر)، ولا تخدع بصفر.

## 7. طبقة النماذج

- **بدون SDK**: HTTP مباشر إلى المزوّد مع بث SSE (`llm/sse.ts`)، مزوّدان متكافئان:
  - `openai.ts` — أي نقطة متوافقة مع OpenAI.
  - `anthropic.ts` — واجهة Anthropic، بما فيها كتل التفكير الممتدة.
- **عقد الأحداث** (`provider.ts`): `text` (الإجابة)، `thinking` (تفكير النموذج — يُعرض مُطهَّراً ولا يُقيَّد في سجل التدقيق لأن التفكير دليل عرض لا دليل إثبات)، `done` (النتيجة + الاستهلاك)، `error`.
- **إعادة المحاولة** (`retry.ts`): الأخطاء العابرة فقط (429/500/502/503/529) تُعاد بتأخير أُسّي مع jitter وحدّ أقصى. أخطاء 4xx لا تُعاد إطلاقاً — خطأ العميل ليس عابراً.
- `provider.ts` يبني المزوّد من الإعدادات؛ `runtime.ts` يحقن الأسرار (من الـ vault، أو متغيّر البيئة كبديل) في البيئة **داخل استدعاء الأمر فقط**، ويرفض بناء المزوّد إن كان `apiKeySecret`/`apiKeyEnv` يحملان مفتاحاً بدل اسم (`config/refs.ts`).
- **سجلّ النماذج** (`registry.ts`): نافذة السياق والتسعير لكل نموذج معروف. النموذج غير المسجَّل = تسعير غير معروف = تكلفة `null` (صحيح، لا تخمين).
- **تطبيع الاستهلاك** (`usage.ts`): يوحّد صيغ المزوّدين المختلفات في شكل واحد، ويميّز بصدق بين "المزوّد أبلغ" و"نحن قدّرنا".

## 7.1 التفكير (`llm/capabilities.ts`)

`thinkingSupport({type, baseUrl, model})` يقرّر من معرّف النموذج والـ endpoint ما إذا كان يدعم التفكير وبأي آلية: `effort` (OpenAI o-series/gpt-5، Gemini)، `budget` (Claude: ميزانية رموز التفكير الممتد)، `openrouter`. نموذج غير معروف = لا دعم = **لا يُرسَل أي بارامتر**. المستوى يُخزَّن لكل نموذج (`models[id].thinking`) ويُرسَل فقط في دورات **العمل**. مع Anthropic تُحفظ كتل التفكير الموقَّعة (`reasoning`) وتُعاد مع دورات الأدوات (شرط الـ API).

## 7.2 محرّك التوفير (داخل `engine.ts` و`anthropic.ts`)

| الآلية | الأثر |
| --- | --- |
| **بادئة ثابتة** | رسالة النظام لا تتغيّر بين الدورات؛ ما يتغيّر (رقم الدورة، آخر الأدلة) يُرسَل في رسالة `[STATE]` أخيرة. هكذا يعمل كاش المزوّدين. |
| **Anthropic cache_control** | على رسالة النظام وقائمة الأدوات وآخر رسالة. |
| **الضغط** (`compactIfNeeded`) | عند تجاوز حدّ ناعم يُقصَّر مخرج الأدوات القديم **دفعة واحدة** (آخر 8 رسائل تبقى). النص الكامل يبقى في سجل التدقيق. |
| **منع القراءة المكررة** | `read_file` كاملة لملف لم يتغيّر mtime وما زال محتواه في المحادثة = ردّ فوري بلا إرسال. |
| **توجيه النموذج** | `agent.cheapModel` للدردشة والأسئلة والوكلاء الفرعيين. |

| الآلية | الملف | الأثر |
| --- | --- | --- |
| **موجِّه النماذج** (قوي / عادي / رخيص، حدّ جودة، تصعيد، تمهّل، توفير، سبب ظاهر) | `core/router.ts`، `core/cost-wiring.ts` | يسأل المحرك `decideRoute()` كل دور ويُصدر حدث `route`؛ ويمكن أن تكون الطبقة على مزوّد آخر مُعدّ (`EngineOptions.providerFor`) |
| **ضغط المخرجات** + `tool_output` + مؤشرات للمتطابق | `core/outputs.ts`، `tools/repo-tools.ts` | ناتج الأمر الطويل يحتفظ ببدايته ونهايته وأسطر الأخطاء؛ والنص الكامل مخزَّن لكل جلسة وعلى بعد استدعاء أداة |
| **خريطة المستودع** و`read_symbol` ومخطط الملفات الطويلة | `core/repomap.ts`، `tools/repo-tools.ts`، `tools/fs-tools.ts` | إيجاد الشيفرة دون قراءة الملفات |
| **ملخصات** الأدوار القديمة (R5) | `core/summarize.ts` | استدعاء واحد لنموذج رخيص؛ تُعلَّم الرسائل `summarized` ولا تُحذف |
| **أربع نقاط Anthropic**، `prompt_cache_key` | `llm/cache.ts`، `llm/openai.ts` | تنجو الذاكرة من الأدوار غير المعتادة |
| **ضبط الهدر**: إيقاف الحلقة، تخطّي إعادة التحقق، أدوات قراءة متوازية (R4) | `engine.ts` | تعمل حين يوجد `EngineOptions.costSettings` |
| **عدّاد الاستهلاك**: الحد، الوتيرة، معايرة النسبة، تقرير التوفير، التوفير | `core/usage-meter.ts`، `core/cost-report.ts`، `server/cost-api.ts` | السجلّ `~/.vara/usage.jsonl`؛ و`/limit` و`/savings` و`/route`؛ وفي الويب `CostMeter`/`CostBoard` |

كل آلية تغيّر ما يراه النموذج (الضغط، الملخصات، المخطط، إيقاف الحلقة، القراءة المتوازية، إعادة استخدام التحقق) معطّلة ما لم يوجد `EngineOptions.costSettings`، والموجِّه بلا طبقات مُعدّة يعيد اختيار النموذج كما في v0.4.0؛ ويمرّر `makeSessionRunner` كل شيء عبر `costExtras()`. دائمة التشغيل: الضغط يحتفظ بأسطر الأخطاء، ونقاط Anthropic الأربع، وسطرا إرشاد في موجّه العمل، وحدث `route`.

العدّادات في `session.savings` وتُعرض بـ `/cost` وفي اللوحة الجانبية. تكلفة الوكلاء الفرعيين تُضاف لسجل الأب فتبقى الأرقام صادقة.

## 7.3 الوكلاء الفرعيون والسرب (`delegate`)

يستدعي `delegate` الدالة `Engine.spawnSubagents` التي تتحقق من الخطة (`planSwarm` في `core/swarm.ts`) ثم تنفّذها (`runSwarm`). الخطة حتى 4 مهام، ولكل مهمة اختيارياً `id` و**دور** و`dependsOn`.

- **الأدوار:** `researcher` و`reviewer` للقراءة فقط، و`implementer` و`tester` قد يعدّلان الملفات؛ ويضيف الدور تعليماته إلى موجّه الوكيل الفرعي. أدوارك الخاصة في `config.json` ← `swarm.roles`. و`kind` الصريح يغلب الدور؛ وفي وضع PLAN كل المهام للقراءة فقط.
- **قائمة المهام المشتركة:** يرى كل وكيل فرعي الخطة كاملة (من يفعل ماذا)، ومهمة تعتمد على غيرها ترى تقارير تلك المهام. لا تبدأ المهمة إلا بعد انتهاء ما تعتمد عليه؛ وإن فشلت إحداها تُتخطّى المهام المعتمدة عليها ويكمل الباقي. الخطة التي فيها معرّف مجهول أو مكرّر أو دورة تُرفض بسبب يفهمه النموذج.
- **الحدود** (`config.json` ← `swarm`، وكذلك الإعدادات ← الوكيل): `maxTasks` ≤ 4 و`maxParallel` ≤ 3 يمكن *خفضهما* فقط؛ و`maxModelCalls` (الافتراضي 120) يُصرف للسرب كله ولا يبدأ وكيل جديد بعده؛ و`maxCostUsd` يوقف بدء وكلاء جدد عند بلوغ التكلفة **المعروفة** له. التكلفة المجهولة لا تُحسب صفراً أبداً، فسقف الاستدعاءات هو الحارس الذي يعمل دائماً.
- **تقرير واحد مدموج:** ترويسة (انتهى / فشل / تُخطّي، الاستدعاءات، التكلفة) ثم كل تقرير بترتيب الخطة؛ وإن عمل وكيل يعدّل الملفات يُطلب من الأب التحقق قبل أي ادعاء.
- **مباشر:** كل تغيّر حالة حدث `subagent` (المعرّف، العنوان، الدور، dependsOn، الحالة `waiting|running|done|failed|skipped`، وكذلك `swarm` — أي نداء `delegate` —، و`kind`، و`steps`، وعند الانتهاء `calls` و`costUsd` (`null` = مجهول، لا يُعدّ صفراً أبداً) و`report` بعد التنقية و`cancelled`)؛ وحدث `swarm_report` يحمل التقرير المدموج والمجاميع. تعرضها الطرفية في المحادثة وفي قسم باللوحة الجانبية وفي `/agents` (§9)، والمتصفح لوحةً.
- **الإلغاء:** `Engine.cancelSubagents(id?)` (عبر `SessionRunner.cancelAgents`) توقف وكيلاً فرعياً عاملاً أو، بلا معرّف، السرب كله: العاملون يُوقفون (`child.stop()`)، والمنتظرون يُتخطّون (`shouldStop` في `runSwarm`)، والوكيل الملغى يُبلَّغ `failed` + `cancelled`، وما يعتمد عليه يُتخطّى بالقاعدة المعتادة. والوكيل الفرعي الذي ينتهي *paused / stopped / interrupted* (خطأ مزوّد، أو ميزانيته) يُبلَّغ **failed** أياً كان النص الذي تركه.
- **استعماله جيداً:** موجّه العمل (`DELEGATION_NOTE` في `core/prompt.ts`) ووصف `delegate` يقولان: أرسل كل المهام المستقلة في نداء واحد (تعمل معاً)، وحدّد الأدوار، واجعل الموجّهات مكتفية بذاتها، ورتّب بـ`id`/`dependsOn`، وتحقق من التقرير المدموج. `tests/delegation-eval.test.ts` يقيسه بنموذج مُمثَّل: ثلاث مراجعات في نداء واحد تتزامن (ذروة التزامن 3 مقيسة)، والاعتماد يسلسل، والإخفاق يتخطى التابعين، والإلغاء يوقف وكيلاً.

كل وكيل جلسة **مؤقتة** (لا تُحفظ ولا تُسجَّل أحداثها) بوضع الأب **وسياسة وضعه المخصّص** ومفاتيح المهارات وMCP للجلسة، وميزانية صغيرة (25 دورة لـ`work` و12 لـ`explore`) والنموذج الأرخص، ولا يملك `delegate`. وتُضاف استدعاءاته إلى سجل الأب.

## 7.4 MCP (`src/mcp`)

`McpClient` يتحدث JSON-RPC عبر stdio (أسطر JSON) أو HTTP (JSON/SSE مع `mcp-session-id`). `McpHub` يدير الاتصالات في الخلفية (خادم معطوب لا يؤثر على غيره) ويحوّل أدوات الخوادم إلى `Tool` باسم `mcp__<server>__<tool>` وبمخطط JSON الخام من الخادم. `readOnlyHint` يحدّد ما يعمل في PLAN وفي الأسئلة. **الأسرار**: الإعدادات تحمل أسماء أسرار الـ vault (`secretEnv`, `bearerSecret`) لا قيمها.

## 7.5 المهارات

`discoverSkills(cwd)`: مدمجة ← `~/.vara/skills` ← `<project>/.vara/skills` (الأحدث يغلب الاسم). الفهرس (اسم + وصف) في رسالة النظام، والمتن عبر أداة `skill` عند الحاجة فقط.

## 7.6.1 الأوضاع المخصّصة (`core/modes.ts`)

يعرّف `config.json` ← `modes` (أو الإعدادات ← الوكيل في المتصفح) أوضاعاً مسمّاة. الوضع **يقوم على** `plan` أو `build` ولا يستطيع إلا التضييق عليه: `allowTools` / `denyTools` (مع wildcards مثل `mcp__github__*`) و`allowCommands` / `denyCommands`. تخزّن الجلسة الأساس في `config.mode` — فتبقى كل قواعد plan/build تعمل أولاً — والاسم في `config.customMode`. تصل السياسة إلى `authorize()` عبر `ToolContext.modePolicy`، وتُستعمل أيضاً لإخفاء الأدوات الممنوعة عن النموذج، ويرثها الوكلاء الفرعيون. والاسم الذي لم يعد موجوداً **يُغلق على الأمان** (قراءة فقط). والضيف لا يختار إلا وضعاً أساسه ضمن صلاحيته. الاختيار بـ`/mode <name>` أو `Tab` (يدور) في الطرفية، أو بالمحدّد بجانب صندوق الرسالة.

## 7.7 إدارة الوكيل لنفسه بموافقة (`tools/self-tools.ts`، `core/selfmanage.ts`)

أربع أدوات تتيح للوكيل تغيير إعداده: `skill_write` و`skill_toggle` و`mcp_manage` و`switch_mode`. لا تعمل واحدة منها وحدها: تستدعي الأداة `ctx.approve()` فيصدر المحرك `approval_request` بالتغيير بدقة (سطر الأمر الكامل لخادم MCP، والنص الكامل للمهارة)، ويضع الجلسة في `waiting_user` وينتظر. يجيب المالك بـ**سماح / رفض** في المتصفح (`POST /api/sessions/:id/approvals/:aid`) أو `/approve` و`/deny` في الطرفية؛ وإيقاف التشغيل رفض. وغياب من يوافق يعني *الرفض*: التشغيل بلا واجهة والوكلاء الفرعيون و**وكلاء الضيوف** (لا يعطي المضيف منفذ الإدارة إلا لجلسات المالك نفسه) لا يستخدمون هذه الأدوات أصلاً. والتغيير نفسه يمرّ عبر `AdminPort` — تنفيذ واحد تشترك فيه الواجهتان. والوضع المخصّص الذي لا يذكر أداةً لا يستطيع استخدامها؛ و`skill_write` و`skill_toggle` و`mcp_manage` للتنفيذ فقط، أما `switch_mode` فتعمل في plan أيضاً.

**وكيل يعرف بيئته (`core/systeminfo.ts`، `tools/system-tools.ts`).** يعرف الوكيل بيئته أيضاً، كمساعد يستطيع فتح إعداداته. `AdminPort.system` (في جلسات المالك فقط — لا يعطيه المضيف لضيف ولا لوكيل فرعي ولا لتشغيل بلا واجهة) يضيف:
- **`vara_system` (قراءة فقط):** `overview` و`settings` و`providers` و`skills` و`skill <name>` و`mcp` و`connectors` و`modes` و`sessions` (هذا المجلد أو `folder` آخر أو `all`) و`session <id>` (`summary|transcript|usage|evidence`) و`usage` و`update` و`host`. متاحة في الأسئلة ووضع التخطيط وأدوار العمل في جلسة تستطيع سؤال المالك؛ لا في الدردشة العادية.
- **تغييرات، كلٌّ خلف `ctx.approve()` وعلى البطاقة التغيير بدقة:** `skill_delete` و`mode_manage` (إنشاء/استبدال/حذف وضع مخصص) و`setting_change` (قائمة مسموحة: `agent.autoIntent|defaultMode|cheapModel` و`ui.*` و`swarm.*` و`updates.check` وميزانيات المهام والأهداف — و**لا** `allowPublish` ولا `agent.browser` ولا `agent.desktop` ولا أمر التحقق ولا المزوّدون ولا المفاتيح) و`connector_manage` (موصّل يحتاج رمزاً لا يتصل إلا إذا كان الرمز في الخزنة أصلاً). مع `skill_write` و`skill_toggle` و`mcp_manage` و`switch_mode` أعلاه، يصبح «اصنع لي مهارة» و«ثبّت خادم MCP» و«أطفئ المهارة Q هنا» و«انتقل إلى الوضع M» أموراً يفعلها الوكيل بنفسه بعد موافقة.
- **الموجّه والمهارات:** `SELF_MANAGE_NOTE` (نص ثابت فيبقى الموجّه مستقراً للتخزين المؤقت) يُضاف فقط حين يوجد المنفذ؛ والمهارات المدمجة `create-skill` و`setup-mcp` و`vara-environment` تعلّم الإجراء.

**قاعدة الخصوصية — تُنفَّذ في الكود وتُختبر في `tests/system-privacy.test.ts`:** لا أداة في هذه العائلة تستطيع إرجاع سرّ. تُسأل الخزنة عن **الأسماء فقط** (`namesOnly`: حقل `hint` في القائمة يحمل أول أحرف القيمة ولا يُمرَّر أبداً)؛ ومفاتيح المزوّدين `vault | env | none` مع *اسم* السرّ؛ وفي MCP تُعرض `env` والترويسات و`secretEnv` بالاسم فقط، وتفقد العناوين بيانات الدخول والاستعلام والجزء، وتُخفى الوسائط بعد `--token`/`--api-key`/…؛ وكل ما سواه — محادثات الجلسات الأخرى ونصوص المهارات وأخطاء الخوادم — يمرّ عبر `scrubSystem` (في `security/redact.ts`: كل ما يزيله `scrubAll` وتعيينات من نوع `password=…` وJWT وأشكال الرموز المعروفة وصيغة رمز VARA ذات الـ43 حرفاً) وتُغلَّف المحادثات بـ`UNTRUSTED_SESSION_DATA`. ولا استعلام يقبل مساراً: الجلسة تُوجد بمعرّفها عبر مخزن الجلسات (المعرّف `[A-Za-z0-9-]{3,64}`) فلا يمكن هنا فتح `~/.vara/vault` ولا `~/.vara/host`. وجلسات المجلدات الأخرى مقروءة لأن وكيل المالك وحده يملك المنفذ.

**مفاتيح لكل جلسة:** `config.disabledSkills` و`config.disabledMcp` تُخفيان مهارة (من الموجّه، فيرفضها `/skill-name`) أو خادم MCP (أدواته وسطره في الموجّه) لجلسة واحدة فقط. في المتصفح: تبويب *الأدوات* في اللوحة الجانبية (`POST /api/sessions/:id/toggle`)؛ وفي الطرفية: `/disable <name>` و`/enable <name>`.

## 7.6 الاستضافة والجلسات المشتركة (`src/server`)

`vara ui` / `vara serve` يشغّل **مضيفاً** على جهازك: خادم HTTP محلي (REST للأوامر + Server-Sent Events للبث الحيّ، بلا اعتماديات). المحرك والمفاتيح والمجلد كلها عندك؛ الضيف يرسل نصاً ويستقبل أحداثاً فقط، ولا يصله أي مفتاح أبداً.

| الملف | المسؤولية |
| --- | --- |
| `access.ts` | الأدوار والصلاحيات (`Grant`)، الدعوات والضيوف (توكنات مخزَّنة كـ SHA-256 فقط)، و`authorize()` — **نقطة القرار الوحيدة** |
| `host.ts` | `VaraHost`: يستضيف الجلسات والمشغّلات، حافظة أحداث لكل جلسة (إعادة بث بـ `after=id`)، استهلاك كل ضيف، وإضافات الجلسة (الأدلة والتكلفة، التصدير، الإيقاف، مهمة↔هدف، البحث عن ملفات المشروع لـ `@`) |
| `http.ts` | الخادم والتحصين |
| `commands.ts` | `vara ui/serve/invite/guests`؛ يملك الإعدادات الحيّة ويبدّل المزوّد عند تغيير الإعدادات |
| `manage.ts` | `Manager`: إدارة المزوّدين والنماذج والإعدادات والمهارات وMCP للمالك فقط (`/api/manage/*`). كل تعديل يمرّ بطابور واحد ثم `apply()` الذي يبني المزوّد أولاً (يُرفض التغيير الذي لا يعمل قبل حفظه)؛ الاعتماديات (الشبكة، الخزنة) تُحقن للاختبار. |
| `ui-assets.ts` | مُولَّد (gitignored) من `ui/` عبر `scripts/build-ui.mjs`: حزمة esbuild للواجهة (React) مضمّنة كنصوص، يقدّمها `http.ts` على `/` و`/join/*` و`/assets/*` بـ CSP صارم. رمز المالك يأتي في `#token=` فيُنقل إلى sessionStorage ويُزال من الرابط؛ الصلاحيات تُحسب في الخادم (`view.can`) والواجهة تعرضها فقط. |

**الأدوار:** المالك (كل شيء) · الضيف بمنحة (`Grant`): `watch` مشاهدة الجلسة المشتركة، `sendShared` الكتابة فيها (تصل للنموذج مسبوقة بـ `[from <اسم>]`)، `ownSession` جلسة مستقلة في نفس المجلد، `modelPolicy` (`locked` | `list` | `any`)، `mode` سقف القوة (`plan` للقراءة فقط | `build`) و`canChangeMode`، `canInterrupt`، سقوف `maxModelCalls`/`maxCostUsd`، وانتهاء. قوالب جاهزة: `viewer` · `participant` · `collaborator`. المالك يعدّل المنحة أو يسحبها فتسري **عند الطلب التالي** للضيف (وتُوقَف وكلاؤه خلال ثوانٍ).

**واجهة API:** `GET /api/me` و`/api/models` و`/api/files?q=` (للمالك)؛ `/api/sessions` (قائمة، إنشاء) و`/api/sessions/:id` ثم `…/messages` و`…/pause` و`…/mode` و`…/model` و`…/share` و`…/kind` و`…/stop` و`…/events` (SSE) و`…/insights` و`…/export`؛ `/api/admin/*` (نظرة عامة، دعوات، ضيوف — للمالك)؛ `/api/manage/*` (مزوّدون، إعدادات، مهارات، MCP — للمالك).

**أيضاً:** `POST /api/uploads` (بايتات خام و`x-file-name`؛ يعيد معرّفاً يُرسَل كـ `attachments:[…]` مع الرسالة)، و`GET /api/sessions/:id/attachments/:file` (لمن يقرأ الجلسة)، و`GET|POST|DELETE /api/sessions/:id/preview` (للمالك فقط).

**قواعد لا تُكسر:**
1. الصلاحيات تُفرض في `authorize()` على الخادم، لا في الواجهة.
2. جلسة ضيف آخر **غير موجودة** بالنسبة لك (404 لا 403).
3. مجلد العمل دائماً مجلد المضيف؛ الضيف لا يختاره، و`allowPublish` مغلق لجلساته.
4. تكلفة غير معروفة ≠ صفر: السقف الذي يحمي المالك حين تكون التكلفة مجهولة هو `maxModelCalls`.
5. تفكير النموذج الخاص لا يُبثّ إلا للمالك.
6. الإدارة (المزوّدون والمفاتيح والإعدادات والمهارات وMCP) وإرفاق `@ملف` والبحث في ملفات المشروع للمالك فقط، ولا يعود أي مفتاح في أي استجابة.

**كخدمة (`vara serve`، `server/daemon.ts`، `server/doctor-server.ts`؛ الدليل: [DEPLOYMENT.md](DEPLOYMENT.md)).** `parseServeSettings` يحوّل الأعلام ومتغيرات `VARA_*` إلى كائن واحد مُتحقَّق منه (المتغير الفارغ يعني «غير مضبوط»؛ منفذ خاطئ أو `--lan` مع `--bind` أو رمز قصير أو مكرر أو `--public-host` مشوّه تُرفض مع السبب؛ وربط غير محلي يحذّر دائماً). وبيانات المالك **بصمة**: `resolveOwnerAuth` يستعمل رمزاً مقدَّماً (ملف/متغير/علم — لا يُخزَّن ولا يُطبع أبداً) أو بصمة SHA-256 المحفوظة في `host/owner-token.sha256` (`0600`) من تشغيل سابق، أو يولّد رمزاً ويعيده مرة واحدة لطباعته ويحفظ بصمته فقط (`--rotate-token` يستبدله). و`startServer({ ownerTokenDigest, trustProxy })` يقارن بزمن ثابت، وخلف وكيل موثوق يعدّ محاولات الدخول الفاشلة حسب آخر قيمة في `X-Forwarded-For` (في فضاء أسماء خاص). و`makeLogger` يكتب `text` أو `json` أو `journal` (أولويات syslog `<N>`) ولا يسجّل أي طلب. و`makeShutdown` ينفّذ الخطوات بالترتيب مرة واحدة بمهلة لكل خطوة (إيقاف الجلسات، إغلاق الرابط العام، قطع الاتصالات، إغلاق MCP)، والإشارة الثانية تخرج فوراً. و`/api/health` (بلا مصادقة) هي الفحص لـDocker والوكلاء. و`vara doctor --server` يفحص الإعداد كله بمجسّات قابلة للحقن.

**التحصين:** ربط على `127.0.0.1` ما لم يُطلب `--lan`؛ توكن سري لكل استدعاء (المالك: عشوائي لكل تشغيل في الـ fragment فلا يُرسل للخادم)؛ فحص `Host` (يمنع DNS rebinding — على LAN تُقبل عناوين IP الخاصة فقط، لا النطاقات) وفحص `Origin` (يمنع الطلبات من مواقع أخرى)؛ تحديد معدل للمحاولات الفاشلة ولتخمين الدعوات؛ حدّ لحجم الجسم؛ رؤوس أمان؛ والأخطاء الداخلية لا تُسرَّب للعميل.

> **تحذير جوهري:** ضيف بقوة `build` = وكيل يشغّل أوامر على **جهازك**. الافتراضي `plan` (قراءة فقط) ويحتاج المالك رفعه صراحة، والأداة تحذّر عند إنشاء الدعوة. الوصول عن بعد (خارج الشبكة) يتم عبر نفق — نفق يشغّله المالك (`--public-host`) أو النفق المؤقت الذي تفتحه VARA (`--share`، §7.7)؛ ولا تملك VARA خادماً وسيطاً خاصاً بها.

## 7.8 استخدام المتصفح، التحكم بسطح المكتب، الموصّلات، تعليمات المشروع

**المتصفح (`src/browser/` و`src/tools/browser-tool.ts`).** أداة `browser` تقود متصفح Chrome أو Edge أو Chromium أو Brave موجوداً على الجهاز (VARA لا يحمل متصفحاً) عبر بروتوكول DevTools بلا اعتماد جديد (WebSocket المدمج في Node 22+؛ وحزم الإصدار تضمّ Node 22). كل تشغيل يستعمل **ملف تعريف مؤقتاً جديداً** تحت `~/.vara/browser` لا متصفح المستخدم نفسه، فلا يصل الوكيل إلى أي حساب مسجَّل فيه. الأمان مفروض في الكود لا بالرجاء من النموذج:
- `policy.ts` (صرف ومختبَر): `localhost` مسموح دائماً؛ المواقع الأخرى تحتاج موافقة (مرة لكل موقع في الجلسة)؛ الشبكات الخاصة وعناوين link-local وعنوان بيانات السحابة مرفوضة؛ قائمة صغيرة مدمجة لمواقع البنوك والعملات الرقمية مرفوضة دائماً؛ وكل طلب فرعي تقوم به الصفحة يُفحص أيضاً، فلا تستطيع صفحة إرسال بيانات إلى مضيف لم يوافَق عليه؛ والتنزيلات مرفوضة.
- لا يكتب الوكيل أبداً في حقول كلمات المرور أو الدفع (`isSecretField`)؛ والعناصر التي تبدو لا رجعة فيها (دفع، حذف، إرسال، تأكيد…) وضغط Enter للإرسال يحتاج كلٌّ منها موافقة؛ وإن لم يوجد من يوافق (الضيوف، التشغيل بلا واجهة) رُفضت.
- نص الصفحة يعود داخل حدّ `UNTRUSTED_WEB_CONTENT` مع تذكير بأنه بيانات. هذا يقلّل خطر حقن التعليمات ولا يلغيه؛ والذي يحدّ الضرر فعلاً هو الضوابط أعلاه (الموقع، الموافقة، عدم لمس الأسرار).
- لقطة الشاشة تُحفظ في مجلد `attachments/` للجلسة وتعود علامة صورة؛ والمحرك يضيف رسالة `[ENGINE]` مخفية واحدة بالعلامات بعد كل نتائج أدوات الدور (انظر ROADMAP R9) فتراها النماذج التي تدعم الرؤية. متوقفة افتراضياً: `agent.browser`.

**سطح المكتب (`src/desktop/` و`src/tools/desktop-tool.ts`).** أداة `desktop` تلتقط الشاشة وتحرّك الفأرة وتكتب كشخص: PowerShell وuser32 على Windows (مُتحقَّق على Windows 10)، و`screencapture` وAppleScript على macOS، و`xdotool` مع `scrot` أو ImageMagick على Linux (مكتوبة على الواجهة نفسها لكنها **غير مُتحقَّق منها** في هذا الإصدار). متوقفة افتراضياً (`agent.desktop`)، ولا تُعرض إلا في جلسات تستطيع سؤال المالك، وتُوافَق مرة لكل جلسة، ولا تتوفر أبداً للضيوف ولا للتشغيل بلا واجهة ولا للروابط العامة. ترفض التصرف والنافذة الأمامية لمدير كلمات مرور أو بنك أو تسجيل دخول أو نافذة أمان، ولا ترسل مفاتيح تخرج من التطبيق (Win+R وCtrl+Alt+Del وAlt+F4…)، وتلصق النص غير اللاتيني أو الطويل بدل كتابته، وتضع سقفاً للإجراءات (40 في الدقيقة و300 للجلسة)، وتعيد لقطة بعد كل إجراء دليلاً، ولها **مفتاح إيقاف**: إيقاف الجلسة مؤقتاً أو نهائياً يلغي الإجراء التالي فوراً (`killDesktop` يُستدعى من `SessionRunner.pause`). الإحداثيات بوحدات بكسل آخر لقطة (مصغَّرة إلى عرض 1280) و`policy.ts` يعيدها إلى الشاشة.

**الموصّلات (`src/mcp/connectors.ts`).** فهرس لخوادم MCP جاهزة (Filesystem وMemory وSequential thinking وContext7 وFetch وPlaywright وGitHub وNotion وSentry وSupabase). إضافة أحدها تحفظ رمزه في الخزنة المشفّرة وتكتب خادم MCP عادياً باسم الموصّل، فيظهر في `/mcp` ويمكن إيقافه لكل جلسة وتصل أدواته للوكيل كأي أداة MCP. لا يُدرج إلا ما فُحصت حزمته أو عنوانه (وكل مدخل يذكر كيف)؛ وموصّلات `*-remote` تسجّل الدخول عبر OAuth (`src/mcp/oauth.ts`، [docs/ar/OAUTH.md](OAUTH.md)): اكتشاف وتسجيل ديناميكي للعميل وPKCE وتحويل loopback مع بديل اللصق وتجديد وإلغاء؛ والرموز سرّ واحد في الخزنة لكل موصّل (`OAUTH_TOKENS_<ID>`) لا يصل إلا إلى ناقل HTTP (مزوّد الرمز في `McpClient`، يُجدَّد عند الانتهاء ومرة بعد 401) ولا يصل إلى الوكيل ولا الواجهة البرمجية ولا الواجهة. في الويب: الإعدادات ← الموصّلات؛ وفي الطرفية: `/connectors` و`vara connectors add <id>` (يطلب الرمز دون إظهاره).

**تعليمات المشروع والتحقق (`src/core/project.ts`).** عند إنشاء جلسة يقرأ VARA الملف `VARA.md` وإلا `AGENTS.md` وإلا `CLAUDE.md` وإلا `.vara/instructions.md` (أول موجود، 8000 حرف كحد أقصى) ويحتفظ به مع الجلسة، فتبقى رسالة النظام ثابتة كل دور. ويُعلَّم كبيانات من المستودع: إرشاد لا إذن. وإن لم يُضبط أمر تحقق يُكتشف من المشروع (`npm`/`pnpm`/`yarn test` إن وُجد سكربت اختبار حقيقي، و`cargo test`، و`go test ./...`، و`pytest`) — وبلا شيء عند الشك.

**الخطة المرئية.** أداة `todo` (للقراءة فقط) تحفظ قائمة مهام؛ واللوحة الجانبية في الويب تعرض أحدثها (ووضع PLAN يسمح بها).

## 9. واجهة TUI

- **Ink** (React للطرفية). الحالة في `App.tsx`، والعرض في مكوّنات صغيرة (`home`, `palette`, `sessions`, `entries`, `markdown`, `sidebar`, `tabs`, `settings`, `providers`, `mcp`, `format`). **الثيم** `theme.ts`: لوحة ألوان حيّة تُبدَّل في مكانها (`applyTheme`).
- **ثبات الإطار**: وضع الشاشة الكاملة (alternate buffer) بإطار بارتفاع `rows-1` (إطار بطول الطرفية يجعل Ink يعيد رسم كل شيء)، والصفوف الثابتة `flexShrink={0}` وإلا انضغطت عند فيض المحتوى. تحديثات البث تُجمَّع كل 80ms. التمرير: عجلة الماوس (SGR 1006) أو الأسهم.
- **`resolveKey` في `keymap.ts` هو سياسة الإدخال الوحيدة**: كل مفتاح يُحوَّل إلى `KeyAction` موحّد، والتسميات والاختبارات تشتق منه. لا معالجات متنافسة مبعثرة.
- **درس تصميمي مُوثّق**: يعيد تثبيت `useInput` كل رسم، وقد يصل مفتاح قبل تسطير التأثيرات → المعالج المرتبط يقرأ اقترانًا قديماً. الحل: **مرآة refs** تُكتب كل رسم (`overlayRef`, `escArmedRef`, `draftKindRef` …) والمعالج يقرأ منها حصراً.
- `Esc` يُغلق الطبقة على **مستوى التطبيق** في `resolveKey` — يعمل حتى قبل تثبيت اشتراك الأوفرلاي، و`onClose` يعيد الإغلاق بأمان (idempotent).
- النص المتعدد الأحرف يصل كـ chunk واحد = لصق؛ يُحافظ على أسطره.

- **الوكلاء (`tui/agents.ts`، `agents-view.tsx`):** مختزِل نقي يطوي أحداث `subagent` / `swarm_report` إلى أسراب من الصفوف (الحالة والدور والاعتماديات والخطوات والنداءات والتكلفة — المجهولة تظهر «cost unknown» لا `$0`)، وهو المصدر الوحيد للعروض الثلاثة: سطر لكل وكيل في المحادثة (يُستبدل في مكانه) مع سطر ملخص حين ينتهي السرب؛ وقسم في اللوحة الجانبية (`ui.sections.agents`، الإعدادات ← اللوحة الجانبية) يعرض آخر سرب؛ وشاشة `/agents` (↑↓ اختيار، Enter التقرير، `c` إلغاؤه، `C` إلغاء الكل، `m` التقرير المدموج، ←/→ الأسراب الأقدم). و`/agents cancel <id|all>` و`/agents report` و`/agents list` تعمل بلا الشاشة. الإعدادات ← Agents فيها حدود السرب (المهام ≤ 4 والتوازي ≤ 3 — تُخفَّض فقط —، وميزانية النداءات، وسقف التكلفة).

القائمة المرجعية للاختصارات: `KEYS_HELP` في `tui/commands.ts` (يُعرض بـ `/help`).

## 9.1 واجهة المتصفح (`ui/`)

React 18 تُجمَّع بـ esbuild داخل المضيف (انظر `ui-assets.ts`):

- **الصفحات:** البداية، الجلسة (المحادثة والمدخل)، الفريق (للمالك)، الإعدادات (للمالك: النماذج والمزوّدون، الوكيل، المهارات، الموصّلات، MCP؛ للجميع: المظهر، هذا المضيف). عربي وإنجليزي (`i18n.ts`، RTL بخصائص CSS المنطقية بما فيها التخطيط والمسار الزمني)، 9 ثيمات، وتخطيط للجوال، وتركيز لوحة مفاتيح ظاهر، واحترام لتقليل الحركة.
- توكن المالك في sessionStorage وتوكن الضيف في localStorage. المنطق الصرف مختبَر في `tests/ui-logic.test.ts` و`tests/ui-workbench.test.ts`، والمسارات التي تعتمد عليها الواجهة في `tests/agents-http.test.ts`.

### التكافؤ بين الطرفية والمتصفح

الطرفية هي المرجع. يسرد `ui/src/parity.ts` لكل أمر وإجراء مفتاح وشاشة كاملة في الطرفية أين يقع في المتصفح؛ ويفشل `tests/ui-workbench.test.ts` حين يكون لأمر أو إجراء مفتاح في الطرفية بلا صف، أو حين يسمّي صفٌّ أمراً لا يسجّله المتصفح، أو حين تنفصل هذه الجداول عن البيانات. و*مكيَّف* يعني المهمة نفسها بطريقة المتصفح (يحتفظ المتصفح بـ Ctrl N وCtrl W وTab لنفسه فلها مفاتيح أخرى)، و*مخطَّط* يعني أن في الطرفية ما ليس في المتصفح بعد.

## 10. البيانات على القرص

```
~/.vara/                    # تُغيَّر بالكامل بمتغيّر البيئة VARA_HOME
├── config.json             # الإعدادات (لا أسرار — فقط اسم السِر المطلوب)
├── vault/                  # الأسرار المشفّرة + حزمة المفتاح المحميّة بالجهاز
├── host/                   # حالة الجلسات المشتركة: الدعوات والضيوف وآخر عنوان للخادم
├── skills/<name>/SKILL.md  # مهاراتك (والمشاريع تضيف <cwd>/.vara/skills)
├── memory/MEMORY.md        # ملاحظاتك بين الجلسات (والمشاريع تضيف <cwd>/.vara/memory.md)
├── proposals/<id>.json     # مهارات اقترحها الوكيل وتنتظرك
├── schedules.json          # المهام المجدولة؛ و schedules/<id>.log سجلاتها
└── sessions/<id>/
    ├── state.json          # لقطة الحالة الكاملة (Session)
    └── events.jsonl        # سجل أحداث كامل (append-only)
```

**الاختيار**: الحالة تُحفظ بلقطة + سجل أحداث، لا بسجل واحد قابل للكتابة فوق نفسه. الاستئناف يقرأ اللقطة، والسجل يبقى للأرشيف والتشخيص — فانقطاع في منتصف الكتابة لا يُتلف التاريخ.

الجلسات تُرشَّح حسب `cwd` (مع مقارنة آمنة على Windows) — `vara sessions` يعرض جلسات المجلد الحالي فقط (و`--all` لكل المجلدات). وتُحفظ اللقطات ذرّياً (كتابة ثم إعادة تسمية) فلا يرى قارئ ثانٍ ملفاً نصف مكتوب.

## 11. حدود التصميم الحالية

هذه **قرارات واعية** لا إغفالات:

- **سياق مقصوص دون تلخيص** — النص القديم يُقص عند الاقتراب من النافذة. التلخيص الذكي مؤجَّل.
- **تسعير نماذج محدود بالسجل** — نموذج غير مسجَّل = تكلفة `null` بالتصميم (صحيح أكثر من تخمين).
- **المزوّد يُغيَّر لكل جلسة لا لكل دورة** — الجلسة تحفظ اسم النموذج لا المزوّد؛ فتح جلسة قديمة بعد تبديل المزوّد قد يرسل اسم نموذج لا يعرفه.
- **الضيوف عن بُعد يحتاجون نفقاً** — نفقاً تشغّله (`--public-host`) أو `--share` الذي يستخدم cloudflared أو ssh؛ لا يوجد خادم وسيط لـ VARA. والمعاينة لا تُعرض للضيوف أبداً.
- **ملف PDF يُرفق كنصه المستخرج** (ملفات PDF النصية البسيطة؛ الممسوحة ضوئياً أو المشفّرة تُرفض مع السبب) — بلا تنسيق ولا صور.
- **قائمة المجاميع في `vara update` من الإصدار نفسه الذي فيه الأرشيف**، فهي تكشف التلف والملفات الخاطئة لا إصداراً تعرّض للاختراق.
- **كشف توقف التقدم بسيط** (عدّ دورات فارغة) — كاشف أدق مؤجَّل.
