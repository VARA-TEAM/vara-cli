## 2026-10-16 · v0.5.2 — web search, memory, OAuth sign-in, eval, stop fix

- **Live web search: `web_search` and `web_fetch`** ([docs/WEB-SEARCH.md](docs/WEB-SEARCH.md)). The agent can look things up on the internet with **no paid API**: a provider chain run from your own machine and IP — DuckDuckGo HTML, Mojeek, your own SearXNG server, an optional real-browser engine (when `agent.browser` is on) and, only if you stored a key in the vault, Brave / Tavily / Serper (never default, never required). Query, max results, recency (day/week/month/year), region and language; `web_fetch` reads one page as capped plain text. On by default (read-only); config `agent.webSearch`, switches in Settings → Agent and `/settings`; the system prompt tells the agent to search for recent facts and cite URLs. Safety: results are wrapped as untrusted content, every request and redirect goes through the browser `OriginPolicy` with pinned DNS (private, loopback and metadata addresses refused), size/time limits, rate limit, small cache, honest user agent. `tests/web-search.test.ts`: 23 tests against a local fake server and recorded HTML. **Verified for real** (`scripts/web-search-smoke.ts`, 2026-10-15, author's Windows PC): DuckDuckGo returned results and `web_fetch` read a real page; **Mojeek answered 403 and public SearXNG instances refused JSON** — so today DuckDuckGo is the dependable keyless path. **Not verified:** the browser engine against real Chrome, and Brave/Tavily/Serper against the real services (fakes only).
- **Fix: a session could not be used after you stopped the agent.** A message sent while the stopped run was still unwinding was queued into the dying run and lost, and a stop pressed while a tool was running was forgotten by the next model call. Now a stop sticks, and a message sent during it starts the session again; messages the stopped run never saw are kept for the next start. Covered by `tests/pause-resume.test.ts`.

- **`vara eval` — an evaluation harness for the cost engine** ([docs/EVAL.md](docs/EVAL.md)). 19 deterministic coding tasks (13 bug fixes, 3 features, a multi-file rename, 2 noisy-output cases), each with an automated check that the runner executes itself. Every task runs with the cost engine ON and OFF (optionally several models, `--repeat`) and the report records pass rate (95% interval), quality delta, tokens, limit units, cost (unknown stays null), turns and time, plus regressions, as JSON + Markdown. `vara eval --offline` uses a scripted model (no network; in the test suite); live runs need `--provider` and `--yes`. The measuring provider of the cost benchmark moved to `src/eval/measuring-provider.ts` and is shared. **Honest status:** only the offline mode has been run (19/19 vs 19/19, about 5% fewer limit units, almost all from one noisy-output task) — that proves the harness and that the engine does not corrupt results, **not** that quality holds with a real model. No real-provider result exists yet.
- **OAuth sign-in for remote MCP connectors** (`src/mcp/oauth.ts`; full guide and your to-do list: [docs/OAUTH.md](docs/OAUTH.md)). The MCP authorization flow — protected-resource and authorization-server metadata discovery, dynamic client registration (RFC 7591) when the server offers it, authorization code + PKCE (S256), `resource`, `state` and `iss` checks — behind new catalogue entries `github-remote`, `notion-remote`, `sentry-remote`, `supabase-remote`. Web: Settings → Connectors → Sign in (opens the service, finishes by itself, with a paste box for a browser on another computer); terminal: `vara connectors login <id> [--port N] [--no-open]` / `logout <id>`. A loopback listener on 127.0.0.1 catches the redirect; on a headless VPS you paste the address instead (or forward the port). Tokens live **only** in the encrypted vault and the redactor — never in an API reply, the browser UI, logs, transcripts or the agent's reach; they refresh by themselves (shared refresh, one retry after a 401), and sign-out revokes at the service when it can and deletes everything. Owner-only (`/api/manage/connectors/:id/login|logout`); the agent cannot sign in or add an unsigned connector. Every address contacted must be https (plain http only on loopback for a loopback server), and private, metadata and credentialed addresses and redirects to them are refused. For services without dynamic registration, `vara secret set OAUTH_CLIENT_ID_<ID>` (+ `OAUTH_CLIENT_SECRET_<ID>`). `tests/oauth.test.ts`: 20 tests against a local fake OAuth/MCP server (PKCE, rotation, concurrent refresh, state/issuer mismatch, paste fallback, revoke, address refusals, the owner API). **Not tried against GitHub, Notion, Sentry or Supabase for real** — endpoints and "dynamic registration expected" come from their documentation; GitHub needs an OAuth app you create first and may not accept its token at all. Limits: addresses are checked as written (no DNS pinning); no device-code flow; custom MCP servers cannot start a sign-in yet.

Three features, all **off until you turn them on**; details, limits and what was not verified in [docs/AUTOMATION.md](docs/AUTOMATION.md). The general idea (an agent that remembers, writes itself playbooks and works on a timer) is the one Nous Research's Hermes Agent popularised; no code or text was taken from it.

- **Memory:** two plain, editable files — `~/.vara/memory/MEMORY.md` (about you) and `<project>/.vara/memory.md` (about the project). A `memory` tool lets the agent view / add / replace / remove notes; by default every agent write waits for your approval (`memory.agentWrites`: ask · auto · off), and a run with nobody to ask is refused. Notes that look like a secret are **refused**, not redacted-and-stored. At most `memory.maxTokens` (default 400) of notes go into the system prompt of your own work and question turns, newest first; chat and sub-agents get none. Manage it with `/memory`, `vara memory`, or Settings → Memory in the browser. Config: `memory.enabled` (default false).
- **Skill proposals:** after a multi-step task the agent may *propose* a new or improved skill with `skill_propose`. A proposal is only a file in `~/.vara/proposals/`; **nothing is installed until you approve** (`/skills proposals|show|approve|reject`, `vara skills …`, or the top of Settings → Skills). Limits: 8000 characters, 3 per session, 20 waiting, secrets refused. Config: `skills.propose` (default false); offered only in your own interactive sessions.
- **Scheduled runs:** `vara schedule add "<every 6h | cron>" "<prompt>"` runs a prompt headlessly in a folder and keeps a log (`list`, `run`, `logs`, `pause`, `remove`, `tick` for cron / Task Scheduler, `daemon`). Off by default (`schedule.enabled`); managed only by the local command (no web route, no agent tool); read-only (plan mode) unless `--build`; never publishes; anything needing approval is refused; stopped after `schedule.maxRunMinutes`; at most `schedule.maxJobs`; missed runs are not replayed. Advances ROADMAP R3 (a goal re-evaluated *inside one session* is still open).
- **Engine:** one additive option, `EngineOptions.memoryBlock`, read in `runTurn` (design note: ROADMAP R13); no permission logic touched.
- **Verified:** unit and integration tests with scripted models (`tests/memory*.test.ts`, `skill-proposals`, `schedule`), including the owner-only HTTP routes and the token budget. **Not verified:** any real provider or a real long-running scheduler daemon; OS-scheduler wrapping; whether real models save useful notes and propose good skills; the new browser pages in a real browser (type-checked and route-tested only); the token budget is a 4-characters-per-token estimate.

## 2026-10-15 · v0.5.0 — the browser workbench, cost engine v2, a system-aware agent, deployment

- **Cost engine v2 — a limit that lasts** (design, research with sources, and every measured number: [docs/COST.md](docs/COST.md)). **Model router:** strong / standard / cheap tiers per turn (a tier may be a model on another configured provider), a quality **floor you set** that no work turn goes below, escalation to a stronger tier after a refused completion or repeated failures, a visible reason for every decision, hysteresis so a long conversation is not re-billed on another model for a few cents; `routing` in the config, `/route`. **Context:** command output keeps its head, tail and error lines with the full text one `tool_output` call away; identical repeated results become a pointer; `repo_map` / `read_symbol` and an outline for files over 1000 lines; old turns folded once into a cheap-model summary (ROADMAP R5, needs a cheaper model; history is never deleted); four Anthropic cache breakpoints and `prompt_cache_key` on api.openai.com. **Waste:** a runaway loop stops after 5 identical calls, a verification command is not re-run when nothing changed, independent read-only tools of one turn run side by side (R4). **Limit meter:** `/limit 5000000 tokens per 5h` (or dollars, or the plan percentage your provider shows — two readings teach VARA what 1% is), pace ("at this rate it lasts N hours"), soft warnings at 70/85/95%, an **opt-in** eco mode that lowers routine turns one tier near the limit (never below your floor), and a savings report with its method stated; web `CostMeter` / `CostBoard`, terminal `/limit` `/savings` `/route`. Unknown usage is counted separately and never as zero. **Measured offline** (scripted scenarios through the real engine, `npx tsx scripts/cost-bench.ts`): −19% limit units on a 33-call session and −42% on a 91-call one versus v0.4.0 (output economics + summaries), −83% / −88% dollars when the router moves work from an opus-priced model to a sonnet-priced one, a runaway loop cut from 60 requests to 5, one verification run instead of three, chat on the cheap tier 95% cheaper, "where is X used" ~9.2k → ~1.3k tokens. **Not proven:** answer quality (the scripts are fixed), live providers, cross-provider tiers against two real endpoints; lowering the floor to *cheap* measured **worse** in limit units (it re-bills the conversation), so the default floor is *standard*.
- **The browser UI is now a workbench, with sub-agents in plain sight:** resizable panes — sidebar | session tabs | side panel | bottom dock | status bar — with drag handles that are real ARIA separators (arrow keys, Shift for big steps, Home/End for the limits, Enter or double-click to reset; they mirror in Arabic), four layout presets (focus, review proof, watch agents, preview the app), the layout and open tabs remembered per browser, panes that give way before the conversation drops under 360 px, and drawers on phones. **Session tabs**: drag to reorder, drag onto the conversation (or `Ctrl \`) for a **split view of two sessions**, a tab whose session is gone drops itself. **Agents panel** (`Ctrl Shift A`, `/agents`, the session header chip and the status bar): every `delegate` run live, with roles, status, a trace of who ran when and who waited for whom (a list view too), steps, calls and cost per agent (unknown cost is never shown as zero), each agent's report, the merged report, and **cancel one agent or all** without stopping the session. The same team is drawn inline in the conversation. A bottom dock holds *Output* (a terminal-like feed; `/last`), *Preview* and *Events*. A session-list filter with a this-folder / all-folders switch (`/sessions --all`), `/help` with both keyboards, and the terminal's other commands and keys the browser lacked: `/last`, `/models`, `/provider`, `/resume`, `/palette`, `/enable`, `/disable`, `/approve`, `/deny`, `/attach`, `/preview start|stop|logs`, `Esc Esc`, `Ctrl+J`, `Alt M`, `Ctrl G`, `Alt+←/→`, `Alt W`, a model filter, and `/status` details (time limit, context, evidence). The parity with the terminal is a table (`ui/src/parity.ts`, [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) §9.1) and a test fails when a terminal command or key has no browser row. **Fixed:** answering an approval card from the browser sent the word "approvals" instead of the request id, so Allow / Decline could not work over HTTP. New: `POST /api/sessions/:id/agents/cancel`. **Verified** in the in-app browser (dark, light, Arabic right-to-left, 1440×900 and a 390×800 phone) against `npm run dev:ui` with a scripted swarm, including a live cancel; the layout math, tabs, swarm model, parity table and both routes are unit-tested. **Not verified:** Safari and Firefox, touch input, a real mouse drag of a tab (the handlers were driven with synthetic drag events), screen readers, and the planned `/limit`, `/savings`, `/route` (the terminal has them; the browser does not yet).
- **The agent knows its own environment (and can never read a secret):** a read-only `vara_system` tool — settings, providers (key *state* and secret *names* only), skills, MCP servers and their status, connectors, modes, sessions in this folder, another folder or all of them (summary / transcript / usage / evidence), usage and cost, update and host status — plus four more approval-gated tools: `skill_delete`, `mode_manage`, `setting_change` (an allow-list; never publishing, browser, desktop, the verify command, providers or keys) and `connector_manage` (only when the token is already in the vault). With the existing skill / MCP / mode tools, "make me a skill", "install an MCP server for Y", "look at my session in folder Z", "what are my settings", "turn off skill Q here", "delete that skill" are things the agent does itself, each change on an approval card (web and terminal). Built-in skills `create-skill`, `setup-mcp`, `vara-environment`. Only the owner's own sessions get any of it. The privacy rule is enforced in code and tested: secret values, vault hints, env values, headers, tokens never come back (`scrubSystem`, names-only listings, no file paths anywhere).
- **Sub-agents, parallel agents and the swarm are visible in the terminal:** a live line per agent in the conversation (role, status, dependencies, steps, time, calls, cost — unknown is never `$0`), a side-panel section, and `/agents` (pick, read a report, cancel one with `c` or all with `C`, the merged report with `m`; `/agents cancel|report|list`). Cancelling stops the running agent, skips the queued ones and what depended on them. A sub-agent that ends paused or stopped (a provider error, its budget) is now reported **failed**, not "done". New Settings → Agents (tasks, parallel, model-call budget, cost cap) and a side-panel toggle. The prompt and the `delegate` description now say "send every independent task in one call"; `tests/delegation-eval.test.ts` measures parallel delegation with a scripted model.
- **Run VARA anywhere — `vara serve` as a service:** settings from flags and `VARA_PORT`, `VARA_BIND`, `VARA_PUBLIC_HOST`, `VARA_CWD`, `VARA_OWNER_TOKEN[_FILE]`, `VARA_LOG`, `VARA_TRUST_PROXY`; an owner token that survives restarts (shown once, only its SHA-256 stored; `--rotate-token`, or your own with `--token-file`); safe defaults (loopback, always a token, a warning on any wider bind); `--trust-proxy` so the login limit sees the real client behind a reverse proxy; log lines for journald (`<6>` priorities), JSON or text; a clean ordered stop on SIGTERM/SIGINT; `vara doctor --server`. New: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) (+ Arabic), `Dockerfile` (non-root, volumes, healthcheck on `/api/health`), `deploy/docker-compose.yml`, `deploy/vara.service`, `deploy/Caddyfile`, `deploy/nginx.conf`, `deploy/vara.env.example`. **Not run here:** Docker, systemd, nginx and Caddy were not available — the files were written and reviewed but never executed.

- **Files and images in the conversation:** drag a file onto the browser composer, paste a screenshot, or use the paper-clip; in the terminal use `/attach <file>`, `@path`, or drag a file onto the terminal. Images go to the model as real image blocks when the model can see (new vision detection, overridable per model; a model that cannot see is told an image was attached, nothing more); text files up to 120 KB and PDFs (their text, no layout) are attached as text. Images are checked by their bytes (SVG refused), limited to 5 MB and 6 per message, and stored inside the session's own folder; a name typed in a message can never make the host read another file.
- **Live preview:** the agent can start your dev server with the new `preview` tool (build mode); the browser shows it inside the session (side panel → Preview) through a loopback reverse proxy on its own port, in a sandboxed frame; `/preview start <command>` prints the URL in the terminal. Only the owner has it — guests never see it, and it is never reachable through a share link.
- **`vara ui --share` — a temporary public link:** opens an outbound tunnel with `cloudflared` or `ssh` (whichever you have; VARA runs no relay), prints one read-only invite on the public address, and closes everything when the time is up (default 2 h), the tunnel dies or the host stops. Your owner token is refused on the public address, and failed-login limits count the real client so a stranger cannot lock you out. A banner in the browser says the link is live.
- **`vara update`:** checks the latest GitHub release, verifies the download against `SHA256SUMS.txt`, runs the new version's self-check, then swaps files in place and keeps the old version for `vara update --rollback`. The terminal and the browser show a quiet "update available" note (one request a day, nothing else sent); turn it off in Settings or with `VARA_NO_UPDATE_CHECK=1`.
- **Swarm upgrade for `delegate`:** tasks get named **roles** (researcher, reviewer = read-only; implementer, tester = may edit; your own in `config.json` → `swarm.roles`), an `id` and `dependsOn` so a task waits for another and receives its report, and every sub-agent sees the shared task list. The swarm shares a model-call budget (default 120) and an optional cost cap that counts only *known* cost (unknown is never zero); `maxTasks` ≤ 4 and `maxParallel` ≤ 3 can only be lowered (Settings → Agent, or `swarm` in the config). The result is one merged report. Status (waiting / running / done / failed / skipped, role, dependencies) is live in the browser and the terminal. Sub-agents now also inherit the parent's custom mode and per-session switches. (The first message a sub-agent sees now begins with its role and the team plan; the task follows `Your task:`.)
- **Per-session switches for skills and MCP servers (connectors):** turn a skill or a server off for one conversation without touching the others or your saved settings — the *Tools* tab in the browser's side panel, `/disable <name>` and `/enable <name>` in the terminal, or by the agent itself (`skill_toggle` / `mcp_manage` with `scope: session`, with approval). A switched-off skill is not in the agent's prompt, so `/skill-name` refuses it; a switched-off server's tools are not offered. A skill change applies from the next message.
- **The agent can manage itself — with your approval, never silently:** four new tools — `skill_write` (create/edit a skill), `skill_toggle`, `mcp_manage` (add/remove/enable/disable an MCP server) and `switch_mode`. Each one shows the exact change (the full command line for an MCP server, the full text of a skill) as an approval card — in the browser (Allow / Decline) and in the terminal (`/approve`, `/deny`) — and the run waits. Headless runs, sub-agents and guests' agents cannot use them (denied, nothing changes); stopping the run declines the request. `plan` mode may still ask to `switch_mode`; a custom mode that does not list a tool cannot use it.
- **Custom modes:** name your own modes beyond plan/build (Settings → Agent in the browser, or `modes` in `config.json`). A mode stands on plan or build and can only *narrow* it with tool and shell-command lists (`allowTools`, `denyTools`, `allowCommands`, `denyCommands`); enforced in `authorize()` and hidden from the model. Pick it with `/mode <name>` or `Tab` in the terminal, or the mode selector in the browser; guests are capped by their grant. A mode that was deleted fails closed (read-only).
- **Working folder in the browser interface:** the session list shows only the current folder's sessions (the owner can ask for every folder); the owner can change the working folder from the sidebar — pick a recent one or browse the machine — and new sessions work there. Sessions already started keep theirs. Guests cannot change or browse folders.
- **Installer:** `install.ps1` no longer fails on Windows accounts whose user PATH is unset.

## 2026-10-14 · Shared sessions (the foundation) · CI

New: `src/server/{access,host,http,commands}.ts`, `src/core/runner-factory.ts`, `.github/workflows/ci.yml`; tests `access` and `server`.

- **The host** (`vara ui` / `vara serve`): a local HTTP server (REST + SSE) hosting sessions; keys never leave the owner's machine.
- **Invites and powers:** `vara invite` creates a link with a grant (watch / write / own session / power ceiling / model lock / call and cost caps / expiry). `vara guests` lists and revokes. Tokens are stored hashed, and an edited or revoked grant takes effect at once.
- **Hardening:** loopback by default, a token on every call, `Host` and `Origin` checks, rate limits, a body size limit, no error leaks.
- **A real race fixed:** saving a session became atomic (write then rename), so a second reader (the session list, another client) never sees a half-written file, and one corrupt session does not hide the rest.

## 2026-10-12 · bfacc81 — enforce the real token budget and unify stall detection

Files: `src/core/engine.ts`, `tests/engine.test.ts`.

**Context (proven from a real stress session `b8026cfb`):** the engine completed 247 calls with no evidence at all (`evidence = 0`) and input grew to **106k tokens against a ~64k window** until the user stopped it by hand. Two proven causes:

- **`toModelMessages` ignored the `requestBudgetTokens`** already computed in `context.ts` and used a fixed character threshold (80,000 characters) that rarely applied → the window was never enforced.
- **The stall counter reset on any tool** — even a **failed** tool adds a result line to the transcript and looks like progress, so the stall was never noticed despite 247 turns.

**The fix:** `toModelMessages` now honours the real `requestBudgetTokens`, walks newest to oldest and drops the oldest tool output first; a message carrying `toolCalls` is never digested (to avoid orphaning its tool results — a provider API error). The stall counter resets only on real progress: **a successful tool** or **a completion claim**; text-only turns and failed tools share one path (`noteNoProgress`) that stops at `STALL_LIMIT`.

**Real acceptance proof** (session `0c9fee55` on a disposable folder): `state=completed` in **9 calls** (not 247), total input **29,427 tokens** (not 106k), independent evidence `node --test` exit=0, and cost `null` with a "pricing unknown" note (unknown ≠ 0). Test suite then: 164/164 in 17 files.
